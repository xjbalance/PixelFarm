# 农场布局与原业务坐标

`FarmLayout` 只保存设施、资源和田块的显示位置与收纳状态。经营数据继续由原系统保存，不新增第二份鱼栏、动物、储物内容或料理队列。

- 住宅进出站位按 `home` 位移，进入室内后仍使用既有 `Housing.anchor()`。
- 种子摊、教学中的林芽目标按 `shop` 位移；恢复椅、野莓、庭院台分别使用 `recovery`、`berry`、`yard`。
- 三个畜舍分别使用 `coop`、`barn`、`fold`。动物存档中的 `position` 仍是原农场逻辑坐标；显示和照料判断转换成当前物理坐标，实际移动回写时调用 `to_logical()`。原动物坐标范围验证保持不变。
- 收纳畜舍隐藏原动物节点、停用其物理处理，并拒绝照料；原动物记录与原日结算规则保留。
- 四个鱼栏、钓鱼点、生态台分别拥有独立布局键。移动天然湖泊只改变湖形与岸线，不偷偷移动这些设施。
- 温室主入口、默认小京站位和仪式返回落点随 `greenhouse`；两张室外研究桌使用独立 `star:desk_left/right`。
- 记忆点 `memory:*`、量尺 `river:*`、约定点 `social:*`、遗迹入口 `explore:*` 独立移动/收纳；原 JSON 保留原始坐标与原剧情内容。
- 特殊小京日程使用相应的实际鱼栏、生态台或独立约定点，不用旧绝对坐标判断是否在场。
- 所有上述业务入口都检查 `active()`。收纳仍返回有限坐标，不能只依赖距离判断。
- 原庭院制作家具继续使用 `Housing.state.placed` 的唯一 ID，移动与回收仍由 `Housing` 负责。可放置范围扩到农场内部，现场合法性复用 `FarmLayoutWorld.check_housing()`，存档校验不依赖当前显示场景。

## 农田事件兼容

田块事件继续携带逻辑 ID。Social、Festival、WorldDevelopment 的合法坐标范围扩为 48×32；对应去重记录允许 1536 个逻辑田块，节日三类农活共 4608 条。没有扩大任务目标或奖励。

春季报名优先挑已有空田，再考虑原 60 个稳定田槽，均排除已收纳田块。只选三格，保留“报名后翻土播种”的原流程，不扫描整张地图把任意未开垦空地选为比赛田。

## 图纸

新增 `farm_editable_base.png` 是原创羊皮纸底图，未烘焙房屋、摊位、道路、湖泊或农田。运行时读取有效地表、当前设施位置、实际田块和原经营家具绘制。资源标记读取稳定资源 ID 对应的新格子，已收纳条目不显示。湖泊详图使用当前湖泊位置的独立坐标映射。

生成脚本：`tools/generate_farm_atlas_base.py`。没有复制商业游戏图像或修改 `need/`。

自动化与窗口结果见同目录总验收报告以及 `builds/farm-layout-business-*.json`；未实际执行的设备测试不能据此视为已通过。

## 庭院页与验证记录

庭院页改用一个「进入农场DIY」按钮和家具清单，不再为46×30区域生成1380个网格按钮。原庭院家具库由DIY的「原物 → 已收纳」接入；普通暂停界面不授予远程布置权限。成长中的花坛可移动，收纳前仍须按原规则采收或撤苗。

专项在隔离用户目录的实际主场景执行：无窗口107项、Xvfb/Mesa真实Godot窗口107项，均0失败且无脚本错误。截图已实际查看：`atlas_home_moved.png`、`atlas_home_stored.png`、`yard_menu.png`。

相关原业务回归12套共1632项均通过。另执行 `housing_c_runner` 的109项，有1条旧断言要求原60格田区永久禁止摆家具，与本次开放空地改造的要求冲突；保留原测试未修改。专项另行验证已开垦田块/作物仍不能被原庭院家具覆盖。原始结果见 `business-regressions.json`。尚无Android真机触控验收。
