# 0.8.1 生产存档兼容说明

审计基线为0.8.0存档v28。旧工单只保存配方ID、批数、起止分钟和完成标记；如果更新改变配方，旧投入说明与产出会按新定义重算。本轮为安全平衡和在制品保护，将根存档升级到v29、工坊区版本升级到2。

仅每笔分钟工单增加 `inputs`、`outputs` 两个数量快照。设备位置、作物、果树、背包、金币、房屋、NPC、小京、矿洞和操作模式仍使用原字段。开始时原子记录实际投入与约定成品；领取按该快照，不临时重算新配方产量。

`resources/harvest/production_080.json` 固定了发布版0.8.0的49条配方。旧v28工单用这份表补快照，原起止时间、完成状态、编号和领取历史不变，不追加扣费，不补发资源。旧厨房四种按日工单保留原兼容入口及日期规则。

`tests/fixtures/quality081_v28.json` 由恢复点 `14287b5` 的原引擎实际输出，使用隔离测试进度，包含已婚、四级住宅、矿洞状态、已完成未领取和仍在加工的订单；不是用户个人存档。生成证明见 [v28-fixture-proof.txt](v28-fixture-proof.txt)。专项验证迁移前后所有非生产字段的值、旧单原料数量、原成品、幂等迁移与坏字段安全拒绝。

同时修复两类输入/恢复边界：

- 金币建造操作拒绝误用临时钻石付款上下文，防止只扣材料而漏扣货币；正常金币报价不变。
- 不同存档复用同一个物件ID时，重新绑定工作动画信号，并把实体、碰撞移回正确地图父节点。

菜单、后台和现实离线时间不会增加游戏分钟；游戏日、睡眠与小睡继续由原 GameClock 管理。动画不调用任何生产结算。
