# 0.8.3 P0：点击与摇杆的任务触发一致性

此阶段基于完成后的0.8.2修复版 `2d427f2`，先修任务与移动，再进行背包等UI改造。存档仍为v30，没有更改任务数据库、章节条件、物品ID、奖励或婚礼要求。

## 真实根因和修复

1. **实际落点被吸回32像素格心。** 东岸要求玩家真实位置x>950。点击(957,496)原先停在(944,496)，摇杆走到(956.08,496)则正常记录东岸事实。现在普通地面保留点击的世界坐标，通过物理方向输入完成末段行走。进一步边界用例发现1像素提前停止也会把点击950.25停在949.83，已保留最后不足1像素的物理移动步骤，没有直接赋值玩家坐标。
2. **任务菱形在物件点击范围以外。** 旧信任务标记绘制在书桌交互点上方，点中标记却被当成墙边地面。标记现在与其原任务物件绑定，走到书桌旁调用原`Story.request`，仍需玩家读完旧信。
3. **导航脚底与真实脚底不同。** 原导航使用20×20方框，角色实际使用直径18的圆。隔离碰撞夹具实测：19像素通道摇杆通过，点击拒绝。导航格心、格边扫掠和动态人物占位现在使用角色实际形状、变换、碰撞掩码和安全边距；两种控制都通过，均无碰撞穿透。
4. **手动交互缺少共同视线检查。** 封闭任务物件的回归发现原手动E可以隔墙开对话。现在点击和手动使用同一合法距离/视线入口。NPC、剧情点和矿道点保留原手动58px范围，设备依照原业务使用54px，农田38px；没有扩大任务区域来掩盖到达失败。
5. **取消遗漏尚未生效的自动农活。** 自动播种起手后点击其他位置或短按方向，旧播种仍会扣种。现在取消请求同时取消其未生效农活动画；已经提交的播种保持原结果，不退款、不重复播种。原摇杆直接操作农活的规则保留。

两种移动原本就都使用`CharacterBody2D.move_and_slide()`，没有发现任务完成条件依赖`control_mode`。修复沿用这一物理控制器及原业务入口，没有另建点击模式任务结算。

## 不可通行位置

普通墙体或占用地面点击，只在点击处64px内寻找与玩家连通的落脚点，并限制不合理绕路。可交互物件继续使用真实对象、距离和视线；被完全封闭的任务点失败并提示，不用邻近地面完成任务，也不绕过未解锁矿道。

## 同档双模式验证

24组任务/操作分别从同一份完整前置存档恢复，通过真实虚拟摇杆触点或地图触点移动，再执行原有交互。包含东岸区域事实、NPC欢迎、住宅/村庄入口、旧信任务标记、桥墩调查、维修记录、风车记录、修桥扣料、胡萝卜交付、第二章运输单、矿洞入口/手册/未解锁出口、翻土、519→520播种、浇水、正常两日成长后的收获、砍树、敲石、小京信件、湖泊恢复记录。

任务前置允许构造已经完成的早期章节；待测试目标的进度、奖励与物品消耗均由实际移动、对话或按钮触发。收获夹具使用真实播种、浇水和过夜，未直接写成熟结果。没有直接将本次测试任务设为完成。

## 文件与回归说明

核心改动：`navigation_manager.gd`的`rebuild`、`clear_segment`、`path_to/ground_path`、`legal_interaction`；`auto_move_controller.gd`的`plan`、`cancel`、`_physics_process`；`interaction_resolver.gd`的`resolve`；`story_point.gd`的标记范围；`main.gd`的手动目标合法性检查。

测试增加`ux083_task_equivalence`、`ux083_navigation_geometry`、`ux083_request_lifecycle`。原测试中要求旧格心落点、未生效旧农活仍继续提交的断言按新要求更新；碰撞、实际库存、任务与奖励断言保留。45度移动方向检查允许因浮点精度造成的约0.00003px轴差，不要求人物因此反复转向。

旧版基线出现过音频退出资源警告，verbose定位为WAV播放对象。`audio.gd`现在仅对正在播放的通道更新暂停状态，停止的通道保持停止；相关回归退出无残留警告。

Android真机尚未具备，本阶段窗口触点、摇杆及多指验证属于桌面实际Godot输入测试，不代表手机手感和性能验收。完整0.8.3仍按后续阶段开发。
