# UI05《沉浸式视野》布局与交互规范

本文按当前 Godot 4.3 工程实际实现记录，作为后续 UI 调整的约束。UI05 在 UI03 背包安全、UI04 共享主题和原点击移动/农活动作基础上调整视野与信息组织。它不新增物品、容量、剧情、资源收益或存档字段。最终全套测试总数由交付报告填写，本文不把阶段专项相加成整体验收结论。

## 一、画布、触区与安全区

共享布局变量在 `scripts/ui/ui_layout.gd`，密度换算在 `scripts/ui/ui_metrics.gd`，主要外层定位由 HUD 的 `reflow_touch_controls()` 和 `reflow_panels()` 完成。

| 变量 | 当前逻辑值 | 用途 |
|---|---:|---|
| 安全区内侧留边 | 12 | 在系统安全区内继续留出边距 |
| 常规间距 | 8 | 控件之间的基础间隔 |
| 面板横向内容内距 | 12 | 纸面内容与细边框的间隔 |
| 常规标题行高度 | 48 | 基础布局参考，实际可随触区/内容增加 |
| 工具显示槽参考 | 48 | 桌面和缺失密度时的最低逻辑尺寸 |
| 快捷工具图标 | 24 | 显示尺寸，不改变原工具素材 |
| 常规正文/标题/次级字 | 18 / 24 / 16 | 共享字号参考，既有对话和特殊标题保留各自字号 |
| 拖动阈值 | 12dp | 按设备密度和画布比例换算，不能直接当固定物理像素 |

**48dp 是手指目标的物理密度要求，不等于固定 48 个画布像素。** 换算公式为：

`逻辑触区 = ceil(48 × DPI / 160 ÷ min(物理宽/画布宽, 物理高/画布高))`

项目正常按钮取该结果和 48 逻辑像素的较大者。实际已验证的校准样本：

| 样本 | 物理视口 | 逻辑画布 | 48dp 对应逻辑触区 |
|---|---|---|---:|
| 320 DPI | 1920×1080 | 1280×720 | 64 |
| 480 DPI | 2400×1080 | 1600×720 | 96 |
| 桌面或密度数据缺失 | 按当前窗口 | 按当前画布 | 安全回退至少 48 |

系统安全区首先由物理屏幕矩形换成画布矩形，再做内部布局；禁止对已经换算的触点重复乘 DPI。现有布局矩阵覆盖 1280×720、1560×720、1600×720、1280×960，模拟左右各 64 逻辑像素安全区，并覆盖 64/96 逻辑触区。高密度时允许面板、按钮和滚动内容增加占位，不以缩小字体或触区换取“看起来更紧凑”。

## 二、常驻 HUD：世界优先，状态分居角落

常驻信息不再铺成全宽顶栏：

- 左上：季节日期、天气、体力文字与细体力条。
- 右上：时间、金币和菜单入口。
- 左下：默认折叠的任务入口；展开后显示原目标和提示，备用摇杆模式下避开摇杆区域。
- 右下：紧凑工具区和独立操作按钮。
- 场景提示与短通知使用轻纸底，最多两行；没有必要的默认空地说明不常驻遮挡世界。

背包、委托和手记仍保留原快捷键；其触屏入口移入游戏内菜单。HUD 节点不承载物品数量、任务奖励或剧情完成状态，仍读原状态模块。工具、剧情和资源变更触发必要更新，不通过每帧重建整套背包或工具节点。

实际捕获的农场常态 HUD 可见输入拦截矩形并集：

| 画布 | UI05 前 | UI05 后常态 | UI05 后工具展开 |
|---|---:|---:|---:|
| 1280×720 | 22.29% | 4.05% | 5.77% |
| 1600×720 | 19.70% | 3.24% | 4.61% |

来源为 `builds/ui05-before-manifest.json` 和 `builds/ui05-after-manifest.json` 的实际窗口帧。这里测的是可见且会拦截输入的 Control 矩形并集，经过视口/祖先裁剪；不是逐像素不透明面积，不计全屏根节点或模态遮罩，也不能用于推导手机帧率。

## 三、三邻槽与完整九工具索引

原九个工具和索引完整保留：锄头、水壶、采收、胡萝卜种子、土豆种子、小麦种子、斧头、镐、鱼竿。`tool_buttons` 数组及每个按钮绑定的原索引不变，不能删掉第九格来匹配更早的八格描述。

常态显示“前一个 / 当前 / 后一个”三邻槽，首尾环绕；旁边的“＋”展开全部工具为 3×3，“−”收起。选择工具后收起为新选择的三邻槽。键盘 1–9、Q 与原工具选择规则继续有效。种子显示实际库存数，其他工具显示原快捷编号；上方短标签显示当前工具名称及种子用尽提示。

**默认工具触区宽度为 204 逻辑像素，不是 180。** 这不包含左侧 64 像素操作按钮，也不包含它与工具区之间的 8 像素间距或安全区边距：

- 三槽网格：`3×48 + 2×4 = 152`。
- 右侧展开按钮：`48`，与网格相隔 `4`。
- 工具区：`152 + 4 + 48 = 204`。
- 加上左侧操作按钮及间距后的整组触区宽度：`64 + 8 + 204 = 276`。

密度增大后的尺寸遵循同一公式：

| 槽位逻辑触区 | 常态工具区宽 | 展开网格高 | 独立操作按钮边长 |
|---:|---:|---:|---:|
| 48 | 204 | 152 | 64 |
| 64 | 268 | 200 | 64 |
| 96 | 396 | 296 | 96 |

网格展开后保持三列与原 0–8 顺序。显示顺序变化不改库存或工具索引。打开模态、换图或选择工具时沿用原取消/收起规则，不能留下先前的待执行农活。已经在生效帧完成的资源提交不因收起工具而回滚。

## 四、纸面与字体

保留 `assets/ui/river` 的 18 张原创 UI 资源。共享 `FarmUIStyle.surface()` 只对九宫格背景角色纹理首次使用时做最近邻半尺寸缓存，九宫格边带由 8 缩为 4 逻辑像素；不把字体、角色、地图或物品图一起缩半，也不改原资源文件来强制适配。

纸面低对比，木色按钮和细边框负责层级；正文深棕，次级文字中棕，成功/自然状态用绿，危险操作用暗红。小京使用普通浅纸底，星紫仅用于其关系标题等少量识别，不把经营设施全部改成紫色。原 NotoSansCJK 字体保留，正文/标题标准沿用；紧凑 HUD 的 12–16 字号状态和工具数字与长对话正文属于不同层级，不以纹理缩半代替字号设计。

按钮仍有正常、悬停、按下、禁用、焦点及选中反馈。图标最近邻采样，浅色工具在一次性展示纹理中保留深色衬底以提高对比；源工具图不改。原人物头像、世界地图和物品颜色不是通用文字色，不做全局染色。

## 五、统一面板与主要页面

面板以安全区、类别首选尺寸和实际内容最小尺寸共同约束。外层不再为每种设施单独手写一套屏幕坐标。当前首选范围为：

| 类型 | 当前首选最大范围 | 布局原则 |
|---|---|---|
| 普通设施 | 960×560 | 中心显示，长内容继续使用原滚动区 |
| 背包/商店 | 1040×540 | 目录与详情分栏，两侧独立滚动 |
| 委托/世界手记 | 1000×600 | 左清单/右详情或既有分页内容 |
| 阅读/恢复说明 | 880×600 | 以正文可读和合法滚动为先 |
| 设置 | 680×540 | 保留原功能，按钮按用途分组 |
| NPC 对话 | 宽不超过1020，普通高度参考240 | 靠安全区下沿；长正文/选项需要时向上扩展 |

这些是类别首选值，不是把大字体、长正文和高密度按钮强行裁进固定盒子的硬上限。HUD 还会核对实际内容最小尺寸与安全区可用空间；对话最小尺寸改变会重新排布，下沿保持可达。

### 背包与商店

目录采用每物品一格的紧凑 selector 网格，种子和收获物分格展示。常用宽度为3–4列；按可用宽度和实际触区适配，不能为列数把触区缩小。右侧稳定详情区显示完整名称、数量和用途，只在选中物品后显示原有使用、装备或交易动作。长卡名可省略，完整信息仍在详情中。

选择本身只读，不消费物品。背包中未选中的零数量卡仅隐藏，节点缓存仍保留；刚用完的当前选中卡保留0和结果，切选其他项后再隐藏。空分类显示“暂无物品”。商店继续按原目录展示，可购买但库存为0的物品不会因此被隐藏。

数量变化、切换选中和购买数量调整不重建整个目录。出售确认放在详情区，保留原冻结数量与确认 token；查看另一物品会收起旧出售确认，不执行交易。付款、配方、价格、容量和物品效果仍由原业务模块校验。

### 委托、世界手记与人物对话

委托/建设页左侧是可滚动任务清单，右侧为原说明、费用、奖励和动作；窄宽度时上下适配。选择任务只更换详情，不交付或领奖。世界手记保持原四页和内容顺序，较小头像及地图实例减少冗余留白。

NPC 对话放在下方，头像为88×96，姓名不再使用厚重底框；正文自然换行，继续、稍后和原剧情选择仍明确分开。选项出现后向上扩展，不把选择按钮推到屏幕外。保留原逐字显示、发言者、肖像身份及完整读完后才提交故事的规则。

### 设施与关系

厨房配方/加工、养殖鱼谱/料理、家具、节日商品和长期建设按轻量卡片分组。共享 `section_grid` 在可用宽度至少760且两张卡的最小宽度确实容得下时使用两列，否则回到一列；不修改任何按钮回调、解锁条件或成本。

社交页先给小头像与人物概要，再将交谈/赠礼和任务详情分区。小京保留好感、信任、羁绊三个独立数值及原520/1314条件，用紧凑摘要展示；没有把三个属性合并为新数值，也没有为美化改变关系进度。

## 六、菜单的实际功能边界

工程没有独立标题/主菜单场景，也没有新建存档、退出游戏、独立音乐/音效滑杆或画质菜单。本次没有创建这些功能。

现有“菜单”是游戏内设置与继续入口：背包/委托/手记、保存/读取、体力恢复、总音乐与环境声开关、操作模式、操作辅助、指南、开发版本地试玩记录和继续游戏。声音/辅助、指南/诊断按行分组，较长的操作模式按钮仍保留足够宽度；床边睡眠使用同一面板的原确认流程。按钮文本和回调仍是原功能，不把视觉重排描述为新增系统。

## 七、跟随镜头、观察与点击

`WorldCameraRig` 只有瞬态 `FOLLOW / FREE_LOOK / RETURNING` 状态。普通大地图内陆跟随以玩家物理脚底锚点 `player.global_position` 为中心，不以头像或精灵包围盒中心代替，也不通过移动角色来满足画面构图。原向上60世界像素的相机偏置和持续位置平滑滞后移除；镜头在玩家物理移动后更新，投影按屏幕像素取整，玩家速度、碰撞精度和原1/1.35地图缩放保留。

中心不是所有地点的绝对约束：

- 地图边缘优先限制在已制作区域，脚底可以偏离屏幕中心，避免露出未制作区域。
- 不足一屏的轴保持制作区域居中。小屋以原房间/已建扩建的绘制边界为准，使用统一室内背景填充；不能因此虚构小屋外的新可走区域。
- 农场制作边界1536×1024，其他大区域1280×896；小屋范围随既有房屋等级变化。

单指或鼠标从非UI地图区域开始、角色静止且无工具动作/自动移动/模态/结算/后台状态时，越过**12dp换算阈值**才进入地图观察。拖动改变镜头，不发角色移动、农活或资源命令；松手保留观察位置。“回中”按钮平滑返回脚底锚点，移动或动作开始恢复跟随，换图/读取、跨日及操作模式切换清理旧观察状态。

模态打开时结束正在进行的拖动；当前代码不要求所有模态关闭后强制回中，已偏移视野仍可由回中按钮或移动/动作恢复。自由观察本身不暂停世界时间，原时钟与日结算规则继续生效。摇杆控制区属于UI，不能借该触点拖动地图；多指、混合设备和取消手势不补发一次点击。

短点仍在**按下瞬间**捕获世界坐标和对象身份，合法释放才提交一次。观察视野中点选远处目标后，镜头可以恢复跟随，但目标仍是按下时那个世界点，不随镜头改变。背包/面板区域沿用UI拦截与原生滚动，不能把列表拖动当成地图观察或物品移动。

## 八、状态保存与后续修改约束

镜头模式、观察中心、拖动手势、HUD展开、面板几何、网格列数、背包只读选中和临时交易确认不新增到存档。加载后按当前屏幕/安全区重新布局并恢复正常跟随。原已保存的工具索引和点击/摇杆偏好继续保存，不能把“不持久化布局”解释为清空玩家操作设置。

背包堆叠仍每ID999，钻石仍走原小京资源字段；没有新增总格数、整理、拆分、装备、交易或奖励规则。各页面继续调用原状态层，前两项优化的动作生效帧、资源一次提交和取消规则不因容器变化而改变。

后续修改应先检查实际矩形、滚动可达性和原生输入，而非只看静态示意。阶段证据包括相机专项48项、工具专项43项、D独立17项、关系/设置相关261项，以及最新布局矩阵301项；它们是各自执行记录，不能混为最终总测试数。前后实际捕获与`builds/ui05-camera-after.json`记录普通内陆中心误差约0.00003屏幕像素，100屏幕像素拖动在1.35缩放下对应约74.0741世界像素；这些是桌面投影与交互测量，不是Android性能数据。

没有Android真机验收，手机可读性、触感、安全区驱动差异、系统后台与实际帧率仍需目标设备检查。完整最终自动化、窗口、制品结果与已知问题以交付报告为准。
