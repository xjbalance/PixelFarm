# 饮食恢复追加调整

根据用户在农田任务02期间追加的要求：现有可食用物品不再按每日份数限制。此调整单独基于农田提交`aef5019`完成，不改农田规则或休息椅次数。

## 实际规则

- 持有对应食物、体力未满时可以继续食用，每次扣1份。
- 胡萝卜/土豆/小麦仍恢复8/12/4；鱼干/鱼汤仍恢复18/30；五种厨房料理保持原22/18/20/24/28。没有改食材价格、配方或产量。
- 恢复值最多到当前体力上限；满体力、缺物品、后台/读取/跨天提交期间不消耗食物。
- 已有料理增益时仍能吃东西恢复体力，但不覆盖、叠层、延长或刷新增益计时；原增益自然结束后，下一份料理正常赋予新单一增益。
- 同步库存/体力通知内不能重入消费。正常的下一次独立点击可以立即继续吃。
- 休息椅仍每日3次，每次20游戏分钟恢复15；茶座每日一次规则保持。

## 实现与兼容

Recovery增加共享瞬态food_busy、begin_food/end_food供基础食物、厨房料理、鱼料理使用。原snacks字段仍饱和在0–3，仅用于旧档兼容，不显示为额度也不再拒绝食用；meal_day仍记录最近料理日以保留原增益保存校验。没有新增存档字段、没有升级schema，v22旧档已吃3份或已用餐也可继续正常食用。

修改仅限recovery_state/recovery_panel、kitchen_state中食用事务与相关说明、aquaculture_state中consume_food与相关说明、两个设施面板的食品文案、inventory_panel食品按钮/提示及tutorial正文。养殖、加工、料理成本、畜牧、矿洞、剧情均未改。

旧测试中“第四份零食拒绝”“厨房与鱼汤共享每日一餐”“有增益时不能再吃”的预期，按照用户明确的新规则改为正常扣物恢复；原满体力拒绝、共享事务防重入、恢复上限、增益不叠加、存档守恒仍严格验证。已更新palm和厨房持久化夹具，在测试旧日额记录仍可食用后恢复该段原状态，后续独立重启继续逐字段核对原证明文件。palm探针只还原食用涉及的物品/体力/兼容记录，避免测试主动重进矿层引发额外探索采样；保留原完整矿层进度对照，六个持久化步骤重新实跑通过。
